# Field-aware product identity: preregistered cross-category check

**Status at freeze:** method and code are fixed before downloading or reading any WDC Headphones or WDC TVs records or gold labels. The WDC Phones held-out test was already reported in PR #7; this follow-up was motivated by its errors. Phones is development evidence only and must not be reported as a new untouched test. Initial commit `d0b1d56` was unusably strict: it accepted zero Phones validation offers. Before external access, the authors' original Phones train/validation records showed that positive pairs frequently had different MPN, GTIN, and color values; we removed those contradiction vetoes and used the explicitly populated `phone_type` as a model identifier. A second Phones-validation adjustment abstains when multiple catalog products share the strongest anchor class. Under its conservative threshold the revised method accepts 13/52 matched correctly, 0/52 matched wrongly and 2/38 naturally unmatched wrongly on Phones validation. These are development figures only. The final freeze SHA is recorded in PR #8.

## Source and scope

- Publisher: [Mannheim CompERBench](https://data.dws.informatik.uni-mannheim.de/benchmarkmatchingtasks/index.html), authors Primpeli and Bizer, CIKM 2020. It lists separate `wdc_headphones` and `wdc_tvs` tasks with three gold-pair files and a record ZIP each. The [original WDC paper](https://webdatacommons.org/productcorpus/paper/WDC-EC_GS.pdf) describes 50 catalog products per category and manually annotated related products/accessories in addition to matches. **The exact augmented-task sizes, complete candidate coverage and number of naturally unmatched queries are not verified until the frozen reader validates them.**
- Primary external task: publisher-hosted **WDC Headphones**; secondary: **WDC TVs**, without method changes after Headphones. The same catalog is used for all queries within a category. This is English offer-to-catalog identity; neither cross-border/bilingual linking nor demand prediction.
- The CompERBench page offers public download but does not state a license for these two archives. Do not infer the Phones ICPSR deposit's CC BY 4.0 license applies to Headphones or TVs. Keep source records/labels out of Git, cite authors and publisher, and resolve reuse terms before redistributing data.

## Frozen method

1. Phones offer-ID split, IDF fit, and baseline are as in PR #7. The new matcher receives the 50 Phones catalog records and the 268 Phones train offers to fit character 3-5 gram document frequency. It uses no Phones test offers or labels; only the 90 Phones validation offers/labels choose **one** score cutoff. External records are inference inputs; they do not refit any statistic or cutoff. Unseen character grams use a fixed weight of 1.
2. Use explicit named product attributes (model, modelnum, phone_type, brand, MPN, GTIN, memory, color, phone carrier, TV dimensions/display, headphone shape/technology, and specifications). Exclude identifiers, URLs, provenance, price, and unknown columns. Product title/description are absent from Phones. Normalize explicit brand and model identifier by lowercasing and removing nonalphanumeric symbols, without alias tables. GTIN uses digits of length 8/12/13/14; MPN/model identifier requires at least four alphanumeric characters. Missing or ambiguous values abstain from that rule; never turn missing into agreement.
3. Reject a candidate if two present, parseable **brand or model identifiers** conflict; model field priority is `modelnum`, `model`, then `phone_type`. MPN, GTIN, memory, and color cannot veto because Phones positive pairs contradict them frequently, so this task measures **author-defined product/model identity, not exact retail SKU equivalence**. An exact matching GTIN anchors rank class 3, MPN class 2, and model identifier class 1. A candidate without one of these three exact anchors is **ineligible**. The character-ngram cosine of explicit attributes orders candidates across distinct anchor classes. If the two leading eligible candidates share the strongest anchor class, abstain rather than guess between catalog variants. If none qualify, abstain. This strict rule can lower coverage; no hidden alternate candidate generation or manual rescue.
4. Phones validation chooses the highest conservative cutoff that maximizes correct accepts subject to *both* false accepted naturally unmatched ≤ floor(0.10 × validation unmatched) and accepted wrong IDs among matched ≤ floor(0.10 × validation matched). A reject-all cutoff is allowed. These are validation constraints, not promised external error guarantees. Once selected, the numeric threshold is applied unchanged to both external categories. No category-specific calibration or adjustment is allowed.

## Locked evaluation

For each external task independently, first hash the four original files, parse the two record tables, combine the **published pair splits** solely as gold, and verify one binary label for every offer × catalog product, at most one match per offer, no duplicate pairs, and a 50-product catalog. Do not use the publisher's pair splits as offer splits: they can repeat offers. If a task fails any condition, report it **inadmissible**, and do not infer no-match by an absent positive in incomplete gold.

If admissible, score each offer once against the **entire 50-item gallery** with the frozen matcher and cutoff. Report counts and denominators for (i) matched correct accepted, (ii) matched wrong accepted, (iii) naturally unmatched false accepted, (iv) matched abstained and unmatched abstained, (v) accepted precision, (vi) coverage, (vii) raw correct top-1 conditional on eligible candidates, and (viii) the file hashes. Show all offers; do not filter hard examples. If Headphones performs poorly, still run TVs unchanged or explicitly mark it unrun. Do not tune and then call a rerun external validation.

No score from this protocol establishes U.S. sales outcome quality, transfer to Chinese listings, business value, or automatic matching safety. A false match must remain a review/abstention item.
